# مُنجز أكاديمي — Munjaz Academic

موقع عربي باتجاه RTL للخدمات والأدوات الأكاديمية. الواجهة HTML وCSS وJavaScript، ويخدمها خادم Node.js مع واجهة استقبال طلبات الخدمات عبر تيليجرام.

## الحالة الحالية

المجمّع والناشر الرسمي ومستقبل الموافقات وعرض الأخبار موجودة مع اختبارات محاكاة، وملف `sources.yaml` يحتوي مصادر مهيأة. نجاح الفحوص المحلية لا يثبت صلاحية الأسرار أو اتصال كل مصدر أو وصول رسائل حقيقية. راجع [تقرير المراجعة الوظيفية](docs/functional-audit.md)، و[دليل الموافقات](news-approval/README.md)، و[دليل المجمّع](collector/README.md).

## تشغيل النسخة الموجودة

1. ثبّت Node.js بإصدار 22 أو أحدث.
2. افتح الطرفية داخل مجلد المستودع.
3. نفّذ `npm test` لفحص الخادم والعامل والناشر والموافقات، ثم `npm start` لتشغيل الموقع.

لا توجد حزم خارجية أو خطوة بناء مطلوبة. يعمل الخادم محليًا على المنفذ 3000؛ مسار `/healthz` يعيد `{"ok":true}`. الصفحة الرئيسية `/` وصفحة الخدمات `/services.html`. تعليمات تفعيل إرسال طلبات الخدمات موجودة في [TELEGRAM_ORDERS.md](TELEGRAM_ORDERS.md). هذه الطلبات منفصلة عن نشر الأخبار ومراجعتها.

## معمارية الأخبار المطلوبة بعد دمج المهام 1–3

```text
مصادر معتمدة ← مجمّع مجدول ← news_queue.json
                             ├─ official → الموقع + قناة تيليجرام
                             └─ unofficial → محادثة المالك
                                               ├─ انشر → الموقع + القناة
                                               └─ تجاهل → ignored.json
```

يمنع `seen.json` تكرار الرابط والعنوان. يحفظ `published.json` نتائج النشر، ويعرض الموقع `news.json`. فشل وجهة نشر لا يمنع الأخرى ويُعالج دون مضاعفة المنشورات. تُفضّل خلاصات RSS/Atom الرسمية مع احترام robots.txt والمهل وعزل أعطال المصادر. بعد خمسة إخفاقات متتالية يُعلَّم المصدر `needs_attention`. العناوين الرسمية تبقى كما صدرت، ويظهر المصدر والرابط والتاريخ مع كل خبر.

## إضافة مصدر جديد: ما يلزم المالك

هذه خطوات مراجعة المصدر، وليست تفعيلًا متاحًا في النسخة الحالية:

1. اختر موقع المصدر الحقيقي وصفحة أخباره أو خلاصته الرسمية؛ لا تعتمد رابطًا تخمينيًا.
2. حدّد اسم المصدر وفئته ورابطه ونوعه. لا يُصنَّف `official` إلا بعد اعتماد المالك؛ غير الرسمي `unofficial` يحتاج موافقة لكل خبر.
3. افتح `sources.yaml` من GitHub واتبع بنية المصدر الموثقة في [دليل المجمّع](collector/README.md). أضف المصدر تحت `sources` بعد التحقق من رابطه وخلاصته أو محدداته، ولا تغيّر `directory_status` إلى `verified` قبل إتمام تدقيق دليل الجامعات كاملًا.
4. اختبر المصدر في وضع تجريبي معزول وتأكد من استخراج عنوان ورابط وتاريخ ومصدر، ثم أعد التشغيل للتأكد من عدم التكرار، قبل تفعيل النشر.

المصادر المعتمدة وفق `AGENTS.md`: قسما أخبار الوزارة وأخبار الجامعات في `mohesr.gov.iq`، وجميع الجامعات الحكومية والأهلية المستخرجة من دليل الوزارة الرسمي. القائمة موجودة في `sources.yaml`؛ وجود مصدر في الملف لا يكفي لتأكيد عمله أو اكتمال تدقيق دليل الجامعات.

## الإعدادات والأسرار

للأخبار بعد تنفيذ المهام السابقة، افتح المستودع في GitHub ثم **Settings → Secrets and variables → Actions → New repository secret** وأضف:

| الاسم | الغرض |
| --- | --- |
| `TELEGRAM_BOT_TOKEN` | توكن البوت من BotFather |
| `TELEGRAM_CHANNEL_ID` | معرّف قناة الأخبار؛ البوت مشرف فيها |
| `TELEGRAM_REVIEW_CHAT_ID` | معرّف محادثة المالك الخاصة للمراجعة |

متطلبات Worker وحماية Webhook، بما فيها `TELEGRAM_OWNER_ID` و`TELEGRAM_WEBHOOK_SECRET` و`APPROVAL_ADMIN_SECRET` و`GITHUB_TOKEN`، موثقة في [دليل الموافقات](news-approval/README.md). أدخل الأسرار المطلوبة للعامل المجاني في لوحة أسراره، دون ملفات أو سجلات عامة. لا تشارك أي توكن في الدردشة أو Git أو الواجهة. `TELEGRAM_CHAT_ID` الموجود في خادم طلبات الخدمات ليس بديلًا عن إعدادات قناة الأخبار ومحادثة مراجعتها.

لتشغيل طلبات الخدمات الحالية يحتاج الخادم `TELEGRAM_BOT_TOKEN` و`TELEGRAM_CHAT_ID` و`SITE_ORIGIN`. المتغيران `PORT` و`BIND_ADDRESS` اختياريان؛ انظر ملف `server/.env.example` دون وضع أسرار في Git.

## تغيير الجدولة والمراجعة اليدوية

الجدولة المطلوبة: الوزارة كل ساعة والجامعات كل ست ساعات. يُعدّل المالك `schedule_hours.ministry` و`schedule_hours.university` في `sources.yaml`، ويطابقها مع `schedule` في ملف سير العمل داخل `.github/workflows/`. مواعيد cron في GitHub Actions تكون بتوقيت UTC؛ توقيت بغداد يسبقها بثلاث ساعات. التشغيل المجدول قد يتأخر، ولا يثبت تعديل الجدولة نجاح التشغيل.

لتشغيل الناشر الرسمي يدويًا افتح **Actions → Publish official news → Run workflow** واختر `main` بعد تجهيز الأسرار والطابور. يعمل الناشر كل عشر دقائق، وتُعدّل جدولتُه في `.github/workflows/publish-official.yml`. راجع [تعليمات الناشر الرسمي](OFFICIAL_PUBLISHER.md) وحدود إعادة المحاولة. يمكن تشغيل المجمّع من **Actions → Collect news → Run workflow**، ويجب مراجعة تقرير التشغيل لمعرفة المصادر الناجحة والمتعثرة. المراجعة غير الرسمية متاحة عبر **Actions → Review unofficial news → Run workflow**: `sync` لإرسال المراجعات، `status` لرؤية الحالات، و`publish`/`ignore` بمدخل `item_id` لقرار المالك اليدوي. عند تعطل Webhook يمكن اعتماد الخبر بهذا الإجراء، أو إعادة إرسال الخبر المعتمد للقناة ثم إدخال رقم الرسالة الحقيقي في `channel_message_id` لتحديث الموقع والأرشيف دون إرسال جديد. يلزم إعداد العامل والأسرار أولاً؛ التفاصيل والحماية وحالات الإرسال غير المؤكدة في [دليل الموافقات](news-approval/README.md). لا تنشر خبرًا غير رسمي قبل موافقة المالك.

## قائمة الإطلاق

- [ ] دمج المهام 1–3 وإتمام اختبار دورة الأخبار ببيانات معزولة.
- [ ] حذف أي بيانات تجريبية «تجريبي:» من ملفات النشر؛ إبقاء عينات الاختبار خارج المحتوى العام.
- [ ] تأكيد عمل Webhook الفعلي واعتماد المالك ورفض الاستدعاءات غير المصرح بها.
- [ ] أول تشغيل مجدول ناجح؛ تحقق من الموقع والقناة وسجل التشغيل.
- [ ] حفظ الأسرار في GitHub Secrets ولوحة أسرار العامل عند الحاجة؛ منع ظهورها في السجلات.
- [ ] تأكيد المالك أن رقم واتساب الموجود في `app.js` هو رقمه الحقيقي؛ لا يُستبدل برقم مخمّن.
- [ ] فحص نهائي عند عرض 390px: لا تمرير أفقي، وكل التنبيهات تعمل، وشريط الأخبار يختفي عند فراغ الأخبار.

الفحوص المحلية ليست نشرًا فعليًا أو تأكيدًا للأسرار أو تشغيلًا مجدولًا ناجحًا. نتائج هذه النسخة وحدودها موثقة في تقرير الجودة.
